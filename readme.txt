# Replication package: The Anatomy of Out-of-Sample Forecasting Accuracy: A Shapley-Based Approach

Daniel Borup, Philippe Goulet Coulombe, David E. Rapach, Erik Christian Montes Schuette, Sander Schwenk-Nebbe.
*Journal of Applied Econometrics*, forthcoming (manuscript MS 16257).

Package version 1.0.1, assembled September 2026. Maintainer: Erik Christian Montes Schuette, Aarhus University,
christianms@econ.au.dk. Corresponding author of the paper: David E. Rapach, dave.rapach@gmail.com.

This package reproduces every table and figure of the paper and its Internet Appendix from the saved
estimation artifacts, and documents how those artifacts were produced from the raw data. The heavy inputs
that are only needed to recompute the artifacts from the raw fitted models (27 GB of models plus Shapley
intermediates, 23 GB compressed) are archived separately; see "Models and heavy intermediates" below.

Method summary: the paper introduces the performance-based Shapley value (PBSV, with its global version GPBSV),
the TS-Shapley-VI, and the model accordance score (MAS), and applies them to forecasting US CPI inflation
(1990:01 to 2024:08, horizons 1, 3, 6 and 12 months, rolling window) with eight machine-learning forecasts
(principal component regression, elastic net, random forest, XGBoost, neural network, and three ensembles)
against an AR benchmark, using 117 FRED-MD series, three Michigan Surveys of Consumers indices, and inflation lags.

## 1. Quick start

Requirements: Python 3.9.x and Poetry (https://python-poetry.org). No Anaconda, no GPU, no compiler.

    poetry env use 3.9
    poetry install
    poetry run python -c "import anatomy, numpy, pandas, sklearn, seaborn, openpyxl, xlrd; print('env OK', anatomy.__version__)"

    poetry run python tools/run_all_tier1.py          # Tier 0 + Tier 1: every table and figure, about 1 to 2 minutes
    poetry run python tools/check_package.py          # integrity checks of the package itself

Without Poetry: `python3.9 -m venv .venv`, activate it, then `pip install -r env/requirements.txt ./packages/anatomy`
and run the same commands with `python` instead of `poetry run python`.

Outputs land in `outputs/`: `tables/` (CSV and LaTeX snippets), `Figures/` (PDF/PNG under exactly the relative
names the LaTeX sources include, so `outputs/Figures` can be placed next to `Anatomy.tex` and
`AnatomyInternetAppendix.tex` as is), `tier0_published_numbers.txt`, `runtimes.txt`, `summary_*.json`.
To compare the regenerated tables and figure lists with the LaTeX sources of the paper:

    poetry run python tools/verify_tables.py --paper <path>/Anatomy.tex --ia <path>/AnatomyInternetAppendix.tex

## 2. What can be reproduced, and at what cost

| Tier | What | Needs | Runtime (authors' machine) | Expectation |
|---|---|---|---|---|
| 0 | Read the published numbers from the saved artifacts (RMSE ratios, MAS) | this package | seconds | required |
| 1 | Regenerate all 4 tables and 32 figure files of the paper and Internet Appendix from the saved artifacts | this package | 1 to 2 minutes | required |
| 1.5 | Recompute the MAS Monte Carlo p-values (1,000,000 draws per cell, seeded) and the referee robustness variants | this package | about 1 hour | required |
| S | Rerun the simulation studies of Internet Appendix Sections A.4 and A.7 | this package | hours; the sim1 study is the heavy one (budget a day) | required |
| G | Recompute the in-sample GPBSV inputs of Internet Appendix Table A.3 | this package + 16 cores | about 2.5 weeks | optional; the aggregated intermediates are shipped |
| 2 | Recompute the Shapley/GPBSV bundles from the raw fitted models | + the models archive (Zenodo) + TensorFlow/shap | days, large RAM | optional; documented |
| 3 | Refit every forecasting model from the data | + the archival Python 3.7 environment; cluster-scale compute | weeks | not expected; documented only |

Tiers 0, 1, 1.5 and S never need the heavy archive: every intermediate they read is in this repository
(about 65 MB, largest file 7.7 MB).

## 4. Data

All data are monthly. Preprocessing is done by `Code/V002/data.py` (FRED-MD transformation codes as in McCracken and
Ng (2016), three-month moving-average terms, twelve inflation lags) and `models.py`. The `DataCacher` class in
`data_cacher.py` reads the pickled snapshots in `Code/V002/_cache/`; if a snapshot were missing it would try to
download the series again, so the ten cache files must stay in place (seven of them are `None` placeholders for
loaders that exist in `data.py` but are not used by the paper).

| Dataset | Role | Source and license | In this package |
|---|---|---|---|
| FRED-MD, vintage downloaded 2024-10-05 (126 columns; 117 series used as predictors, CPI-U all items `cpiaucsl` is the target) | predictors and target | McCracken and Ng (2016), Federal Reserve Bank of St. Louis, https://research.stlouisfed.org/econ/mccracken/fred-databases/. Public. The historical monthly vintage files are the reference; the "current" download link used by `data.py` no longer serves this vintage | `Code/V002/_cache/get_fred_md_raw.bin` (raw), `get_fred_md.bin` (transformed); plain-text copies `Data/csv/fred_md_raw_2024-10-05.csv`, `Data/csv/fred_md_transformed_2024-10-05.csv` |
| University of Michigan Surveys of Consumers: index of consumer sentiment (`soc_ics`), index of consumer expectations (`soc_ice`), index of current economic conditions (`soc_icc`), retrieved 2024-10-05 from the public tables `tbmics.csv` and `tbmiccice.csv` | three predictors | Surveys of Consumers, Survey Research Center, University of Michigan; copyright The Regents of the University of Michigan; source: sca.isr.umich.edu, retrieved 2024-10-05 (https://data.sca.isr.umich.edu, free download, no registration). The usage agreement restricts redistribution of the data; the three aggregate index series are included here only as a small archival copy so that the exact input vintage can be verified, with attribution; the Surveys of Consumers (umich.soc@umich.edu) inspected this archival copy and confirmed in September 2026 that its inclusion with this attribution is acceptable. A fresh download of the public tables reproduces the series up to historical revisions, since the tables are living files | `Code/V002/_cache/get_soc.bin`; plain-text copy `Data/csv/soc_2024-10-05.csv` |
| `Data/Variable_list_CPI.xlsx` | variable names and groups used in tables and figures | authors' own metadata | yes |

`tools/export_data_csv.py --check` verifies that the CSV copies are identical to the pickled caches. Internet
Appendix Table A.1 lists 118 FRED-MD abbreviations; `s&p:indust` is listed but is not present in the 2024-10-05
vintage, so 117 FRED-MD series enter the models (`tools/verify_tables.py` reports this comparison).

## 7. Computing environment

Language: Python 3.9 (the authors used 3.9.13). Package manager: Poetry; `poetry.lock` is the authoritative list
of versions (numpy 1.22.0, pandas 1.1.5, scikit-learn 0.24.1, xgboost 1.3.3, scipy 1.10.0, statsmodels 0.14.0,
matplotlib 3.6.3, seaborn 0.12.2, openpyxl 3.1.0, xlrd 1.2.0, joblib 1.2.0, tqdm 4.64.1, anatomy 0.1.6).
`xlrd` is pinned at 1.2.0 as in the original environment (2.x dropped `.xlsx` support under pandas 1.1.5).
`env/requirements_*.txt` are the recorded package lists of the estimation environments (provenance).

Operating system: developed and run on Windows 11; all Python code is OS-independent, and Tiers 0 and 1 and the
reduced-configuration simulations were also run on Linux (Ubuntu, Python 3.9.23) while assembling this package. The one Windows-only file is the PowerShell orchestrator
`revision/mas_referee_response/run_pipeline_h3h6h12.ps1` (a convenience wrapper; the Python commands it runs are
listed inside it). Figures request the Arial font; where it is absent matplotlib falls back to DejaVu Sans, which
changes the typography but not the content.

Hardware and runtimes: the revision-stage artifacts (MAS Monte Carlo, in-sample GPBSV, simulations) were produced
on an AMD Ryzen 9 7950X (16 cores, 32 threads), 64 GB RAM, Windows 11; the forecasting run (Tier 3) and the
Shapley computations (Tier 2) ran on Sander Schwenk-Nebbe's Linux workstation (the `/FAST_STORE` storage referenced in
`pred_rev.py`), in October 2024 (run id `20241005_091334`). Tier 0 plus Tier 1 take about one to two minutes; `tools/run_all_tier1.py` appends measured
times to `outputs/runtimes.txt`. Tier 1.5 (MAS Monte Carlo, 1,000,000 draws per cell, seed 20260602 in
`mas_referee_variants.py`) takes about one hour. Tier S: the convergence-band study takes hours; the sim1 study
(25 seeds, three DGPs, three models, 400 Shapley iterations) takes up to a day; `--smoke` runs reduced
configurations in minutes. Tier G is memory-bandwidth-bound and takes about 2.5 weeks on the machine above.
No GPU is needed for any tier.

Randomness: the forecasting run uses seed 43210 (`_runs/20241005_091334/config.json`); the simulation scripts
and `mas_referee_variants.py` seed their generators. `iml_rev.rankdiffs2_w` draws from the unseeded global numpy
generator, so a recomputation with `override=True` reproduces the cached MAS values and p-values to the reported
precision but not bit for bit; the seeded independent recomputation in `mas_referee_variants.py` ("Current" block)
is the reference for Table 1.

## 8. Tier 1.5, Tier S and Tier G commands

    poetry run python tools/run_all_tier1.py --tier 1.5          # MAS Monte Carlo recompute + variants -> outputs/mas_referee_variants
    poetry run python tools/run_all_tier1.py --tier S --smoke    # simulations, reduced configurations (minutes)
    poetry run python tools/run_all_tier1.py --tier S            # simulations, full configurations (hours)

Through the driver, Tier S writes to `outputs/simulations/` (convergence bands, the sim1 scenario folders with
their paper post-processing, and the three-DGP figure set) and leaves the committed reference outputs in
`revision/simulations/outputs/` untouched. Note that `build_sim1_referee_three_dgp_figures.py` reads the scenario
folders from the committed location (hard-coded in the script), so the figure set it writes is always built from
the reference scenario outputs. The authors ran the scripts in place, from `revision/simulations/`:

    poetry run python scripts/revision/run_gp_bsv_convergence_bands.py
    poetry run python scripts/revision/run_sim1_trap_dgps.py
    poetry run python scripts/revision/postprocess_sim1_paper.py
    poetry run python scripts/revision/build_sim1_referee_three_dgp_figures.py --clean

which rewrites `revision/simulations/outputs/`; compare with the committed reference outputs with `git diff` and
restore them with `git checkout -- revision/simulations/outputs`.

Tier G (in-sample GPBSV, Table A.3 inputs), from the package root:

    poetry run python revision/mas_referee_response/compute_insample_gpbsv_v5.py --horizons 1 3 6 12
    poetry run python revision/mas_referee_response/mas_referee_variants.py --include-insample-gpbsv --n-sims 1000000
    poetry run python revision/mas_referee_response/make_paper_vs_isgpbsv_table.py

Not included: the forecast-loss workbooks and the `create_tables.py` / `mhspa.R` route of the original submission,
which covered a shorter out-of-sample sample (2000:12 to 2021:07). No published exhibit is computed from them; the
published Table A.2 comes from `perf_raw.pickle` / `ys_upd.bin` (1990:01 to 2024:08). They are available from the
authors on request.

## 9. Models and heavy intermediates (Tiers 2 and 3)

The raw fitted models (`Models/20241005_091334.7z`, 7.2 GB compressed, 27.4 GB unpacked: four horizons times
416 per-period model files) and the Tier-2 intermediates (`anatomy_h{1,3,6,12}_upd.bin`, about 1.2 GB each;
`ishapley_h{1,3,6,12}_upd.bin`, about 1.7 GB each; the window caches of the in-sample GPBSV computation) are
archived on Zenodo: DOI 10.5281/zenodo.22877061 (https://doi.org/10.5281/zenodo.22877061). `Models/README.md` gives the SHA-256 checksums, where to place
each file, and the environment variable `IML_MODELS_DIR` that `iml_rev.py` and `iml_rev_ishapley.py` read
(default `../../Models` relative to `Code/V002`, i.e. the extracted archive in `Models/20241005_091334/`).

Tier 2 additionally needs `tensorflow==2.5.0` and `shap==0.42.1`, which are not in `pyproject.toml` because
TensorFlow 2.5 pins numpy below 1.20 and Poetry's resolver rejects the combination; the authors installed them into
the same environment with `poetry run pip install "tensorflow==2.5.0" "shap==0.42.1"` (pip only warns). Sequence:
`iml_rev_ishapley.estimate(h)`, `iml_rev.estimate(h)`, `iml_rev.anatomize(h)` for each horizon.

Tier 3 (`pred_rev.run_pred()` with `_runs/20241005_091334/config.json`) was run with Python 3.7.9
(`env/pyproject-refit-py37.toml`, `env/requirements_iml.txt`) on a cluster-scale machine; `pred_rev.py` still
contains the estimation machine's storage paths (`/FAST_STORE/IML_MODELS`), left as documentation of the original run.
